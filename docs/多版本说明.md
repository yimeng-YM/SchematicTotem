# 多版本维护

1.3.0 的支持范围为 Minecraft Java 1.20 至 26.3，共 24 个正式版本，依据 Mojang 和 Fabric 公开版本清单确定。快照版本不在该发布的支持范围内。

上游清单：
- https://meta.fabricmc.net/v2/versions/game
- https://piston-meta.mojang.com/mc/game/version_manifest_v2.json

## 版本目标

`versioning/versions.json` 锁定每版 Minecraft、Java 字节码、Yarn（旧版）、Fabric Loader、Fabric API 与 Mod Menu 编译接口。
每个 jar 的 Minecraft 依赖为精确版本，避免把相邻版本的渲染接口混用。

| 游戏版本 | Java 最低版本 | 源码与渲染接口 |
|---|---|---|
| 1.20 / 1.20.1 / 1.20.2 / 1.20.3 / 1.20.4 | 17 | Yarn、旧式直接顶点绘制 |
| 1.20.5 / 1.20.6 / 1.21 / 1.21.1 / 1.21.2 / 1.21.3 | 21 | Yarn、旧式直接顶点绘制 |
| 1.21.4 / 1.21.5 | 21 | ItemRenderState 特殊模型 |
| 1.21.6 / 1.21.7 / 1.21.8 | 21 | ItemRenderState、GUI 渲染状态 |
| 1.21.9 / 1.21.10 / 1.21.11 | 21 | 有序渲染命令队列 |
| 26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3 | 25 | 原生 Mojang 名称、统一方块模型与新版 GUI |

## 源码组织与分支

`main` 展示当前多版本源码，`feature/multiversion` 保留完整矩阵开发分支；`mc/<版本>` 为每个正式版提供默认构建目标。`baseline/1.21.11` 与标签 `v1.2.1-mc1.21.11` 保留原始的 1.2.1 发布源码。
版本分支共享同一套差异层，默认版本以外仍可用 `-Pmc=<版本>` 构建。这样修改通用逻辑时可以统一检查所有版本，避免复制 24 份维护源码。

- `src/main`：1.21.11 共享基线。
- `ports/legacy`：旧 API 的标准化四边形、方块模型、NBT 与直接绘制。
- `ports/item-state`、`block-parts`、`gui-state`、`command-queue`：各 API 家族的覆盖源码。
- `ports/modern`：本模组源码迁移至 Mojang 名称后的 26.x 基线。
- `ports/native-model` 等：26.x 方块、液体、预览和第一人称差异。
- `versioning/prepare.gradle` 与 `transform.gradle`：确定性的源码组合和版本差异转换。生成结果在 `build/versions/<版本>/generated`；不要手改生成文件。

## 验证边界

`./scripts/build-matrix.ps1` 执行每版生产构建与三项 JUnit 测试，并检查无跳过、版本元数据、字节码最低 Java 版本和成品类路径。结果写入 `build/verification/matrix/`，成品写入 `dist/1.3.0/`。

`./gradlew.bat runSmokeClient -Psmoke -Pmc=<版本>` 启动隔离客户端，使用真实游戏资源烘焙原创样例，在配置界面绘制预览并截图后退出。结果在 `run/compat/<版本>/`。
该检查不覆盖全部物品展示场景、第三方模组组合和所有显卡驱动。世界内的第一/第三人称、掉落物、展示框和触发动画由 1.21.11 现有 Client Game Test 检查；其他版本仍应结合实玩反馈维护。

各发布版本的实际验证结果见对应 Release 附件。构建、GUI 与世界场景验证按检查类型分别记录。
